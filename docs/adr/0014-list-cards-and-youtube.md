# ADR 0014: 一覧のカード表示と YouTube の埋め込み

- 日付：2026-10-16
- 状態：採用（ローカル workerd と Chromium / WebKit で検証。実際の YouTube への接続は未検証）
- 関係する設計：§4.1（一覧：カード表示）、§10.3（リンクカード）、§12（性能）
- 変更するもの：一覧の見た目（行 → カード）、YouTube の URL の行（カード → 埋め込みプレイヤー）
- 依頼：ユーザーから「一覧を Cosense のようなカードにしたい。カードには最初の画像・リンクカード・YouTube のサムネイルを出したい」「YouTube の URL を埋め込みプレイヤーにしたい」

## 決定

### 一覧はカードのグリッド

- 正方形のカードを `repeat(auto-fill, minmax(10rem, 1fr))` で並べる（スマホは 2 列、PC は 4 列）。
- カードにはタイトル（2 行まで）と、**ページで最初の画像**を出す。画像がなければ、本文の最初の数行を文字で出す（記法は取り除き、コード・空行・カードの行は飛ばす）。
- 画像の候補（ページ内の順番）：アップロードした画像（`[asset:…]`）、URL だけの行（リンクカード・YouTube）の画像。**最初の候補に画像がなければ次の候補**を使う（最大 5 件）。

### サムネイルの候補は保存時に、画像は読み出し時に決める

- 保存時に本文を解析し、候補を `pages.thumbs_json`（マイグレーション 0006）に `["asset:{id}", "url:{url}"]` の形で保存する。`links_json` と同じく、保存 API がサーバーで計算する派生データ（クライアントからは受け取らない）。
- 画像の URL は**一覧を読むときに**解決する。アップロードの完了やカードの画像の取り込みは、ページの保存より後に起こるため。一覧の 1 つの問い合わせの中で `json_each` と `assets`・`link_previews` の結合を行う。
- 一覧の rows read は 1 ページ（30 件）あたり 31 → 95 行になった（10,000 ページでも同じ。時間は p95 2ms、ローカル）。
- 0006 より前に保存したページは、次の保存で候補が入る。ローカルの既存データは `pnpm --filter web db:backfill-thumbnails` で入れられる（版は増やさない）。本番にはまだデータがない。

### YouTube は「サムネイル＋再生ボタン」、押してからプレイヤーを読み込む

- URL だけの行で、URL が YouTube（`youtube.com/watch`・`youtu.be`・`/shorts/`・`/embed/`・`/live/`、`m.`・`music.`）なら、カードの代わりに 16:9 の枠を出す。`t=` / `start=` の開始位置も使う。動画 ID は 11 文字の `[A-Za-z0-9_-]` だけを受け付け、プレイヤーの URL は ID から組み立てる（入力の URL をそのまま iframe に入れない）。
- 最初はサムネイルと再生ボタンだけを表示し、**押したときに** `https://www.youtube-nocookie.com/embed/{id}?autoplay=1` の iframe に置き換える（1 回押せば再生される）。
  - 公開ページを開いただけでは YouTube に接続しない（プライバシーと表示速度。プレイヤーは多くの JS を読み込む）。
  - プライバシー強化モード（youtube-nocookie.com）を使う。
  - CSP に `frame-src https://www.youtube-nocookie.com` だけを追加した。
  - JavaScript がなければ YouTube へのリンクになる。⌘ / Ctrl クリックは新しいタブで YouTube を開く。
- エディタでも、カーソルのない行は同じ見た目で、その場で再生できる（再生ボタンのクリックで本文は変わらない）。

### YouTube のタイトルとサムネイル

- 以前は YouTube のページの HTML から OGP を読もうとしていたが、取れなかったため、カードにならず URL の文字のままだった（実際の YouTube がどう応答していたかは確認していない）。
- YouTube は HTML を取得せず、**oEmbed**（`https://www.youtube.com/oembed?format=json&url=…`）でタイトルとチャンネル名を取り、サムネイルは `https://i.ytimg.com/vi/{id}/hqdefault.jpg` から取る。どちらも既存の取得の安全策（本人の操作時だけ、リダイレクトの再検査、サイズ・時間の上限）を通す。
- サムネイルは他のカードの画像と同じく R2 に取り込み（ADR 0012）、外部の画像を直接表示しない。これが一覧のサムネイルにもなる。
- oEmbed に失敗してもサムネイルは取り込み、10 分後に再試行する（通常のカードは 24 時間後）。プレイヤーは ID だけで動くので、失敗しても再生はできる。

## 代案

| 代案 | 採用しなかった理由 |
|---|---|
| ページを開いた時点で iframe を置く（Cosense と同じ） | 公開ページの閲覧者が再生しなくても YouTube に接続し、大きな JS を読み込む。見た目と操作（1 回押すと再生）は同じにできる |
| サムネイルを `i.ytimg.com` から直接表示する | ADR 0010・0012（外部の画像を直接表示しない）に反する。CSP の `img-src` も広がる |
| 一覧を読むたびに本文全体を解析して最初の画像を探す | 本文全体（最大 256KiB × 30 件）を D1 から読むことになる |
| 画像の URL まで保存時に確定する | アップロードやカードの画像は保存の後に完了するので、古いままになる |

## 未検証・残るリスク

- **実際の YouTube の oEmbed と i.ytimg.com からの取得**（自動テストは偽の応答で行った。ローカルの `pnpm dev` では実際に接続する）。
- 実機（iPhone Safari）での埋め込みプレイヤーの再生と全画面表示。
- 縦長の動画（Shorts）も 16:9 の枠に入る（左右に余白が出る）。
- YouTube 以外の埋め込み（Vimeo、X など）は対象外。
