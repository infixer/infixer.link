# ADR 0015: オフライン・outbox・三者比較による競合解決

- 日付：2026-10-16
- 状態：採用（ローカルの wrangler dev と Chromium で E2E 検証。実機の iPhone / Android、Service Worker の更新の流れは未検証）
- 関係する設計：§4.3（自動保存）、§4.4（オフライン・PWA）、§17 Phase 6
- 変更するもの：ADR 0008 の「競合 UI（最小版）」を三者比較に置き換える。SvelteKit の `paths.relative` を `false` にする

## 決定

### Service Worker（`src/service-worker.ts`）

| 対象 | 扱い |
|---|---|
| アプリの殻（ビルドの immutable ファイル・static・`/offline`） | インストール時に版ごとに保存し、cache-first |
| 公開ページの HTML（ナビゲーション）と SvelteKit の `__data.json` | network-first。成功した公開の応答を最新 200 件まで保存し、オフラインではそれを返す |
| 保存していないページ（オフライン時） | `/offline` を返し、「この端末にまだ保存されていないため開けません」と表示する |
| `/api/*`、`/owner*`、`/media/*`、リダイレクト、`no-store` の応答、他オリジン、GET 以外 | 一切扱わない |

- **登録は本人の端末だけ**。殻は gzip で約 240KB（エディタを含む）なので、読者にはバックグラウンドでもダウンロードさせない。本人のセッションを確認した端末に印（`localStorage` の `infixer-link:owner-device`。トークンは保存しない）を付け、その端末でだけ登録する。
- **更新は勝手に適用しない**。新しい版は待機させ、「新しいバージョンがあります［更新する］」を表示する。押されたら下書きを IndexedDB に書き出してから `skipWaiting` → 再読み込みする。
- **`paths.relative: false`**：`/offline` を別の URL の代わりに返すと、相対パスの JS / CSS / リンクがその URL の下で解決されて壊れるため（E2E で発見）。
- 保存した HTML には、そのときの CSP nonce がそのまま入っている。この HTML は自分のサーバーが生成したものなので、オフライン時に nonce が再利用されても、注入される内容はない。

### オフラインでの本人と編集

- オフラインでセッションを確認できないとき、印のある端末なら「オフラインの本人」として扱い、保存済みのページのエディタを開く。CSRF トークンは空で始め、接続後の最初の送信で 403 → セッションを読み直して再送する（既存の仕組み）。セッションが切れていれば `auth-required` になり、下書きは残る。
- 印はセッションが切れても消さない（未送信の下書きを見守るため）。消すのは、ログアウト時に「ダウンロードしてから削除」を選んだときだけ。

### outbox：開いていないページも送る

- **IndexedDB の下書きが outbox**（ページごとに 1 件。内容・元の版・送信中の mutationId を持つ）。開いているページはエディタが送り、それ以外は `lib/offline/outbox.ts` が、アプリを開いたとき・接続が戻ったとき・タブが表示されたとき・「今すぐ送信」で送る。Background Sync API には頼らない（iOS にない）。
- 古い順に送る。画像が参照されていれば、先に画像を送る（未送信の画像を含む版は公開しない。ADR 0012）。
- **送れなかったものは消さない**。競合は印を付けて本人の判断を待つ（再送しない）。拒否された画像・保存できない内容は理由を付けて待つ。通信・セッションの問題では止まる。
- **二重送信を防ぐ**：Web Locks API でページごとのロックを取る。エディタは下書きを読む前にロックを取る。同期が送信中ならそれを待つ（最大 3 秒。別のタブで同じページを開いている場合は待たずに続ける）。outbox は、ロックが空いていないページを飛ばす。ロックを待たずに下書きを読むと、同期とエディタが同じ下書きを別の mutationId で送り、偽の競合になった（既存の E2E で発見）。
- 一覧は `/offline`（ヘッダーの下に「未送信の変更が N 件あります」）。開く・ダウンロード・削除（ダウンロードしてから）・すべてダウンロード・今すぐ送信ができる。

### オフラインで作るページ

- 「新規」と「今日の日記をこの端末で書く」（オフライン時の `/today` などで表示）は、クライアントで UUID を作り、`create` の印を付けた下書き（`baseRevision: 0`）にする。編集は `/offline?draft={id}` で行う。
- 接続が戻ったら `POST /api/owner/v1/pages` に同じ `id`（と `dailyDate`）で作成する。応答が失われても、同じ mutationId で再送すれば一度だけ作られる。
- **別の端末が同じ日の日記を先に作っていた場合**：サーバーは `daily_conflict` に既存のページの id を付けて返す（`details.pageId`）。エディタは「サーバーの日記の末尾に追加して開く」と「ダウンロード」を出す。追加は普通の編集として送るので、その間にさらに変更があれば、下の三者比較になる。
- 無題のページのタイトルには、id の先頭 4 文字を付ける（名前の重複は、サーバーに届くまで分からないため）。

### 競合は三者比較（`packages/sync`、`ConflictResolver.svelte`）

- 下書きに**共通の元版**（`base`：最後にサーバーで確定した内容）を保存する。保存していない古い下書きは、元版が分からないものとして全体を 1 つの競合にする。元版は `GET /api/owner/v1/pages/{id}/revisions/{revision}` でも取れる。
- 行単位の diff3（Myers の差分。差が 4,000 行を超える場合は中央をまとめて 1 つの変更とする）。結果は「変更なし」「この端末の変更」「サーバーの変更」「両方で同じ変更」「重なった変更」に分かれる。
- **重なりがなければ**「まとめて保存」を 1 回押せば保存する。**重なりがあれば**、ブロックごとに「この端末」「サーバー」「両方を残す」を選ぶ。タイトルも同じ考え方で決める。
- ほかに「この端末の内容で上書き」と「サーバーの版を使う（この端末の内容はファイルに保存）」も選べる。**どれも本人が押すまで保存しない**（自動で書き換えない）。

### 容量・持ち出し・ログアウト

- エディタを開いたときに `navigator.storage.persist()` を求め、使用量が 90% を超えていれば知らせる。IndexedDB に書けないときは、これまでどおり `quota-error` と「下書きをダウンロード」を出す。
- すべての下書きと未送信の画像を 1 つの JSON（画像は data URL）でダウンロードできる。
- ログアウト時、未送信のものがあれば「端末に残してログアウト」「ダウンロードしてから削除してログアウト」「キャンセル」を選ぶ。削除を選んだ場合は、下書き・画像・保存したページ・端末の印・Service Worker を消す。

## 代案

| 代案 | 採用しなかった理由 |
|---|---|
| Background Sync API | iOS Safari にない。開き直せば再開できる方式で足りる |
| 読者にも Service Worker を登録する | 読者に約 240KB を余分にダウンロードさせる。オフラインの対象は本人の下書き・直近のページ・作成済みのページ（設計 §1.2） |
| CRDT・文字単位のマージ | 設計どおり初期は採用しない。行単位の三者比較で、重なりを本人が選べば足りる |
| 重なりのない変更を確認なしで自動マージ | 設計は「自動 merge は非重複変更だけでもよい」だが、知らない間に本文が変わるのを避け、1 回の確認にした |
| `/offline` を prerender する | prerender のページは CSP をハッシュで出すため、CodeMirror が差し込むスタイルに nonce を付けられない（ADR 0011 と同じ問題） |

## 未検証・残るリスク

- **実機**（iPhone Safari のホーム画面追加・アプリ切り替え後の復帰、Android Chrome）でのオフライン編集と復帰。
- **Service Worker の更新の流れ**（バナー → 下書きの保存 → 再読み込み）は自動テストしていない。
- Web Locks API のないブラウザでは、エディタと同期が同じページを同時に送ることがある（mutationId で重複はしないが、偽の競合になりうる）。
- 端末の保存領域がブラウザに消される（eviction）場合、`persist()` が認められていなければ下書きは失われうる。
- 保存したページの HTML は最新 200 件まで。古いものから消える。
